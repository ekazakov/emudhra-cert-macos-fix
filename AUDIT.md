# Технический аудит — 01.11.2026

Изучены package.json, lockfile, README, все пять CLI, оба общих модуля и исходные тесты. Архитектура JavaScript ESM сохранена; зависимости не добавлены.

## Среда и исходные данные

- macOS, Darwin 27.2.0, arm64; Node.js 26.13.0, npm 12.2.1.
- `npm ci --offline --ignore-scripts` успешно переустановил настоящий zx 8.8.5 из локального кэша по lockfile. У zx нет install scripts; ESM-импорты и реальные процессы проверены.
- Все 16 SHA-256 intermediates и оба целевых корня совпали с опубликованными JSON; отпечатки дополнительно вычислены из DER через X509Certificate.
- Источники: [intermediates](https://emudhra.we-have-a-problem.com/impacted-intermediates.json), [roots](https://emudhra.we-have-a-problem.com/roots.json), [страница инцидента](https://emudhra.we-have-a-problem.com/), [рекомендации Apple](https://support.apple.com/en-us/149555). Снимки публичных JSON сохранены в tests/fixtures; тесты не требуют доступа к ним по сети.
- В roots.json четыре корня. Изменение системного bundle по-прежнему ограничено двумя корнями из рекомендаций Apple; AAA удаляется только с явным --include-aaa. Перечень не обновляется автоматически при запуске.

## Исправления

- Неатомарный вызов install заменён на Node fs: приватный кандидат в том же файловом разделе, sync, проверка, rename. Сохраняются uid/gid/mode. Ошибка до rename оставляет оригинал целым.
- Добавлена блокировка одновременных записей наших CLI, повторная проверка inode/содержимого, отказ от символьных и дополнительных жёстких ссылок. Чтение открывает файл с O_NOFOLLOW и проверяет тип через дескриптор. Проверяется соответствие бэкапа исходному снимку, а не только текущему файлу.
- Убран автоматический rollback, который мог затереть параллельное стороннее изменение. При ошибке после commit сообщается путь к бэкапу.
- --force обходит только защиту от сторонних различий, а не валидацию PEM/X.509; работает также для валидного bundle с неизвестной структурой секций.
- Отсутствие обязательного файла/явно заданного пути и недоступность Python/Node CA API отражаются как UNKNOWN. Неустановленные стандартные Homebrew-пути остаются опциональными.
- Python проверяет активные default verify paths, не приравнивая неиспользуемые compile-time fallback paths к действующему хранилищу.
- curl запускается с первым аргументом -q: пользовательская конфигурация не может отключить проверку через insecure. Node TLS получил общий таймер, охватывающий DNS lookup.
- Дедупликация монитора учитывает одновременно findings и unknown. Ошибка osascript не подтверждает доставку, поэтому следующая проверка повторит попытку.
- Установщик проверяет ошибки print/bootout, останавливает старую службу до обновления модулей, удаляет устаревшие зависимости в установленной копии перед копированием. Исправлен противоречивый комментарий о ссылке на node_modules.
- Парсер аргументов отклоняет имена свойств прототипа. Добавлен .gitignore для зависимостей и локального состояния.

## Результаты проверки

Исходные 10 тестов прошли; после исправлений **30/30**, без пропусков, с настоящим zx. Помимо искусственных CA добавлены тесты опубликованных DER/отпечатков, пустого/повреждённого PEM, отдельных корней, обеих целей, intermediates, повторного удаления, эксклюзивного бэкапа, атомарной замены и восстановления, сторонних изменений и --force, ошибок записи/доступа, ссылок, inode race и блокировки, отсутствующих Python/Node-компонентов, сетевого отказа/таймаута, кавычек и массивов аргументов zx, ошибок уведомления и повторных вызовов управления службой.

Реальные безопасные проверки macOS:

- `/etc/ssl/cert.pem`: 128 сертификатов, emSign=1, AAA=1. Оба dry-run удаления отработали без записи; список бэкапов пуст.
- Keychain: системные корни, системное и пользовательское хранилища прочитаны через security. Первый запуск в песочнице дал ошибку User Keychain; она корректно попала в UNKNOWN. При разрешённом внешнем read-only запуске все три источника прочитаны успешно.
- Публичный plist с пробелами и XML-спецсимволами принят реальным plutil. Реальный launchctl print отсутствующей службы вернул 113; обработка этой ситуации покрыта тестом.
- Checker дополнительно запущен с абсолютным Node и окружением только PATH=/usr/bin:/bin и HOME: JSON сформирован, код завершения соответствует findings. Пользовательский Keychain в песочнице остаётся UNKNOWN. Это отдельная проверка ограниченного окружения, а не запуск внутри launchd.
- Read-only --live-all: 28 TLS-проверок, UNKNOWN отсутствует. Системные `/usr/bin/curl` и `/usr/bin/python3` приняли каждый из четырёх хостов (включая No CT). Node.js отклонил каждый с CERT_REVOKED; четыре найденных Homebrew Python отклонили каждый из-за отсутствия локального издателя. Результаты относятся к этим исполняемым файлам и текущему сетевому окружению; перехватывающий TLS-прокси может влиять на вывод о доверии клиента.

## Оставшиеся ограничения

- Не запускались реальное удаление/восстановление системного bundle, sudo и изменения Keychain. Для записи системных сертификатов необходимо отдельное разрешение владельца.
- LaunchAgent не устанавливался и не удалялся. Реальные bootstrap/bootout/kickstart, повторная установка, минимальное окружение launchd, сон/пробуждение/перезагрузка и видимость уведомлений остаются для следующего интеграционного этапа. Сейчас расписание и ошибки управления проверяются модульно, без регистрации службы.
- Обновление установщика не транзакционно: ошибка после остановки старой службы может оставить расписание остановленным. Требуется устранить причину и повторить установку.
- Блокировка действует только между нашими CLI. Node fs не предоставляет compare-and-swap для rename; остаётся окно между последней проверкой и заменой при записи сторонним процессом. Не запускать одновременно с обновлением macOS. После аварии возможна оставшаяся блокировка; её нельзя снимать, пока процесс ещё работает.
- ACL, extended attributes и file flags системного файла не копируются. Сохранение этих метаданных и работа с нестандартной конфигурацией /etc/ssl требуют отдельной проверки до записи в такой среде.
- Проверен Node 26.13.0; отдельная матрица минимального Node 22.15 не выполнялась. Не покрыты все venv, менеджеры версий, контейнеры и приложения со встроенными CA.
- Сетевые тесты охватывают четыре опубликованных DV-цепочки; отсутствие принятия этих цепочек не доказывает отклонение всех вариантов всех 16 сертификатов.
