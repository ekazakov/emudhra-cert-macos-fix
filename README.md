# eMudhra macOS — JavaScript + zx

Полная JS-версия комплекта для проверки CA, обратимого изменения `/etc/ssl/cert.pem` и ежедневных уведомлений macOS. Комментарии к операциям и проверкам написаны на русском языке.

## Требования

- macOS; Node.js **22.15+**; npm.
- Пакет [`zx`](https://google.github.io/zx/) устанавливается локально через `npm ci` из lockfile.
- `sudo` требуется **только** при реальном удалении или восстановлении системного CA-bundle.
- Стандартные `/usr/bin/security`, `/usr/bin/curl`, `/usr/bin/osascript`, `/usr/bin/plutil`, `/bin/launchctl` необходимы для соответствующих функций ОС. Замена bundle выполняется средствами Node.js.
- Python 3 используется *только* для чтения его собственного SSL-контекста и для необязательных сетевых TLS-тестов Python. Для остального используются JS, Node `crypto.X509Certificate`, `fs` и `tls`.

## Установка

Из каталога проекта:

```bash
npm ci
node check-emudhra-certs.mjs
node check-emudhra-certs.mjs --live
node check-emudhra-certs.mjs --live-all
node check-emudhra-certs.mjs --json
```

Вместо `sh script.js` используйте **`node script.mjs`**. Все скрипты написаны как ES modules. Пакет `zx` нужен для системных вызовов, но большая часть логики работает на чистом JS.

## Удаление корней с резервной копией

```bash
node remove-emudhra-certs.mjs --dry-run --include-aaa
sudo "$(command -v node)" remove-emudhra-certs.mjs --include-aaa
node check-emudhra-certs.mjs --live
```

Без `--include-aaa` удаляется **только** `emSign ECC Root CA - G3` (если он присутствует). С флагом также удаляется `AAA Certificate Services`, что **может нарушить легитимные TLS-подключения**. Скрипт сверяет точные SHA-256 этих корней, их заголовки из формата Apple и число сертификатов до и после; создаёт неперезаписываемую резервную копию в `/etc/ssl/cert.pem.emudhra-backup.YYYYMMDD-HHMMSS.PID`.

### Восстановление

```bash
node restore-emudhra-certs.mjs --list
node restore-emudhra-certs.mjs --backup /etc/ssl/cert.pem.emudhra-backup.YYYYMMDD-HHMMSS.PID --dry-run
sudo "$(command -v node)" restore-emudhra-certs.mjs --backup /etc/ssl/cert.pem.emudhra-backup.YYYYMMDD-HHMMSS.PID
```

Замените путь на конкретное имя из `--list`. Дополнительно принимается `/etc/ssl/cert.pem.orig`. Скрипт создаёт копию **текущего** bundle `cert.pem.before-restore.*` до замены.

Если содержимое отличается не только двумя целевыми корнями, восстановление **запрещено**, поскольку иначе можно отменить обновление безопасности Apple. Опция `--force` снимает этот запрет, но применять её следует только после осознанного сравнения версий. После восстановления повторите `check --live`: возвращение корней может снова разрешить опасные цепочки.

Удаление и восстановление проверяют резервную копию, записывают и синхронизируют кандидата в приватном каталоге рядом с bundle, затем заменяют файл через `rename`, сохраняя владельца и POSIX-права. Символьные ссылки на файл и файлы с дополнительными жёсткими ссылками не принимаются для изменения. Наши CLI используют блокировку `cert.pem.emudhra-lock`; после аварийного завершения она может остаться. Удалять её вручную можно лишь убедившись, что операция больше не выполняется.

Непосредственно перед заменой повторно проверяются inode и SHA-256. Это обнаруживает изменения во время подготовки, но не обеспечивает общей блокировки с обновлениями macOS: не выполняйте обе операции одновременно. ACL, extended attributes и file flags при замене не переносятся. Если проверка после записи не проходит, скрипт сообщает ошибку и путь к бэкапу; автоматического отката поверх возможных чужих изменений нет. `--force` никогда не разрешает повреждённый или пустой PEM.

## Ежедневный запуск через launchd

```bash
node install-emudhra-monitor.mjs --time 09:00
# Дополнительно проверять TLS напрямую через текущие Node/Python:
node install-emudhra-monitor.mjs --time 09:00 --live-all
```

Установщик запускается **без sudo**. Он помещает JS-файлы и `node_modules` в `~/Library/Application Support/eMudhraAudit` и регистрирует пользовательский LaunchAgent `local.emudhra.certificate-audit`. Передача в `launchd` **абсолютного пути к Node** сохраняет работоспособность при минимальном PATH, но после удаления/обновления менеджером версий этого Node нужно переустановить монитор.

```bash
# Тест локального Notification Center:
"$(command -v node)" "$HOME/Library/Application Support/eMudhraAudit/run-emudhra-monitor.mjs" --test-notification
# Немедленный запуск в launchd:
launchctl kickstart -k "gui/$(id -u)/local.emudhra.certificate-audit"
# Полный журнал проверок:
tail -n 100 "$HOME/Library/Logs/emudhra-certificate-audit.log"
# Удаление расписания, без удаления журналов:
node install-emudhra-monitor.mjs --uninstall
```

Монитор проверяет системный `curl` в режиме `--live`, а в режиме `--live-all` ещё Node.js и обнаруженные Python. Уведомления отправляются только при **новых или изменившихся** находках либо изменении набора недоступных источников. Состояние доставки сохраняется после успешного вызова `osascript`; при его ошибке следующий запуск повторит попытку. Успешный вызов не гарантирует видимость баннера при отключённых уведомлениях или Focus.

При обновлении установщик останавливает предыдущую службу перед копированием файлов. Ошибки `launchctl print`/`bootout` не скрываются, кроме явного отсутствия службы. Если копирование, проверка plist или `bootstrap` завершились ошибкой, расписание может оставаться остановленным: устраните причину и повторите установку. Установка не является транзакцией.

## Что означает отчёт

В интерактивном терминале выделяются только ключевые слова: `REJECTED` — зелёным, `UNKNOWN` — жёлтым, `ACCEPTED` — красным. В скрипте удаления `DRY-RUN` жёлтый, `ERROR` красный, «Готово» зелёное. Переменная `NO_COLOR` (включая пустое значение) отключает цвет; терминал `TERM=dumb` также получает обычный текст. При перенаправлении соответствующего потока в файл или pipe цвет отключён. JSON `--json` и журналы монитора не содержат добавленных цветовых кодов.

Ненулевые счётчики `emSign=…`, `AAA=…`, статус `REVIEW` и описание найденного корня выделяются жёлтым; нулевые счётчики остаются обычными. Статус `COMPROMISED` и описание точно идентифицированного скомпрометированного intermediate выделяются красным. В удалении названия запланированных к удалению корней жёлтые. Итоговая строка `RESULT` целиком зелёная при `exit=0`, красная при `exit=1`, жёлтая при `exit=2`.

- **REVIEW** — корень найден в проверяемом хранилище; само по себе это **не доказывает уязвимость**.
- **COMPROMISED** — найден точный SHA-256 одного из 16 известных скомпрометированных промежуточных CA, включая code-signing.
- **ACCEPTED** — TLS-клиент принял тестовую цепочку; это более сильный сигнал, требующий устранения.
- **REJECTED** — TLS-клиент отказал по причине проверки сертификата.
- **UNKNOWN** — таймаут, сетевой сбой или недоступность хранилища; **не означает безопасность**.
- Exit codes: `0` — нет находок/неопределённостей в проверенной области; `1` — есть находки (возможен также `unknown`, проверяйте JSON); `2` — неполная проверка без находок либо ошибка CLI.

Keychain отображается информационно. Присутствие корневого CA в Keychain не означает, что встроенные API Apple доверяют скомпрометированным промежуточным сертификатам. Встроенные версии `pip` могут иметь отдельный certifi. Скрипт не охватывает автоматически все контейнеры, venv, Electron-приложения или версии Node/Python, установленные через `mise`/`pyenv`. Для сетевых тестов через прокси результат может отражать доверие прокси, а не самого клиента.

## Тесты

```bash
npm test
```

Тесты используют искусственные X.509-сертификаты, создаваемые **только для тестов** через OpenSSL, и публичные сертификаты из первоисточника в `tests/fixtures` (снимок от 01.11.2026). Закрытых ключей инцидента в проекте нет. Файловые изменения выполняются во временных каталогах; TLS-тест таймаута открывает локальный TCP-порт. В ограниченной песочнице для него может потребоваться разрешение. `zx` устанавливается настоящим `npm ci`, без тестовой замены.

**Проверка 01.11.2026:** 30 тестов прошли на macOS arm64 с Node.js 26.13.0, npm 12.2.1 и zx 8.8.5. Проверены реальные read-only вызовы Keychain, curl, Python, Node TLS, `plutil`, оба dry-run удаления. Системный curl и `/usr/bin/python3` приняли все четыре тестовые цепочки; текущий Node.js и найденные Homebrew Python отклонили их. Реальная установка/переустановка LaunchAgent, `bootstrap`/`bootout`/`kickstart`, отображение уведомлений, работа после сна/перезагрузки и запись системного bundle не проверялись. Подробности: [AUDIT.md](AUDIT.md).
